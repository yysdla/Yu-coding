- 维护人：产品负责人
- 权威范围：requirement_scope, requirement_status

## 背景

业务、产品、研发和测试需要在飞书协作群中围绕同一个软件项目讨论。现有资料分散在飞书文档、多维表格、会议纪要和 GitHub 中，成员经常重复确认项目范围、开发安排和测试安排。

## 当前范围

ProjectLens 第一阶段必须支持：

- 查询项目总览和当前需求范围；
- 查询需求相关的已有约定；
- 查询 GitHub Issue、Pull Request、Commit 的只读信息；
- 判断是否存在开发安排和测试安排；
- 返回来源、版本、更新时间和当前不确定性；
- 对无法确认的问题生成知识缺口。

## 不在本次范围

- 自动修改飞书文档、多维表格或 GitHub；
- 自动创建或分派任务；
- 自动改变需求、开发、测试或发布状态；
- GraphRAG 和复杂角色化回答。

## 验收条件

- 用户在项目群中 @Agent 提问时，回答必须基于当前项目授权资料；
- 事实结论必须带 Evidence 引用；
- 资料冲突时必须展示冲突及选择依据；
- 资料不足时必须明确说明缺口，不能猜测。
