项目计划及里程碑

ProjectLens 试点项目计划及里程碑

一、项目目标

通过 ProjectLens 自身项目验证跨部门项目沟通助手的实际价值。

重点验证：

多来源资料是否能够被统一检索。
Agent 是否能根据证据回答项目问题。
Agent 是否能识别资料冲突和知识缺口。
不同部门是否能减少重复沟通和人工查找时间。
管理者是否能更快掌握风险、阻塞和决策事项。

二、当前项目状态

总体状态：进行中

当前阶段：试点资料准备与接入准备

整体风险：中

当前最大问题：

GitHub 开发资料尚未全部补齐。
测试执行记录和 CI 证据尚未形成。
飞书文档内容仍需要统一格式和来源标记。

三、阶段计划

阶段一：资料整理和优先级定义

时间：2026-09-10 至 2026-09-12

目标：

整理正式需求文档。
整理项目计划。
整理会议记录。
整理测试安排。
整理业务经营周报。
明确各类资料的来源优先级。
标记已确认、未确认、历史提议和资料缺口。

交付物：

ProjectLens 试点需求说明。
ProjectLens 试点启动会纪要。
ProjectLens 试点项目计划。
ProjectLens 测试安排。
ProjectLens 项目周报。

状态：进行中。

阶段二：资料接入和索引

时间：2026-09-13 至 2026-09-17

目标：

接入飞书文档。
接入飞书多维表格。
接入会议记录。
接入 GitHub 项目资料。
保存来源链接、文档类型、更新时间和权限信息。
验证资料是否可以被检索。

交付物：

资料清单。
来源元数据。
文档索引。
权限检查结果。
首批检索测试结果。

依赖：

飞书文档权限可读取。
GitHub 仓库地址已确认。
各类资料拥有明确的维护责任人。

状态：未开始。

阶段三：LLM Wiki 整理

时间：2026-09-18 至 2026-09-21

目标：

根据源文档生成项目概览。
生成需求范围说明。
生成开发和测试状态说明。
生成当前风险和知识缺口说明。
标注每段内容对应的源资料。
保留源文档和 Wiki 内容之间的关联。

注意：

LLM Wiki 是阅读层，不是新的事实来源。如果 Wiki 与源文档冲突，应以优先级更高的源文档为准。

状态：未开始。

阶段四：群聊试点

时间：2026-09-22 至 2026-09-26

目标：

在群聊中使用 @ProjectLens 提问。
验证业务、产品、研发、测试和管理者的典型问题。
验证回答是否提供证据。
验证 Agent 是否能识别未知和冲突。
验证知识缺口是否被记录。

重点问题：

当前需求范围是什么？
是否已经安排开发？
是否已经安排测试？
当前项目阻塞是什么？
本周有哪些风险？
哪些事项需要管理者决策？
当前还缺哪些资料？

状态：未开始。

阶段五：试点评估和收敛

时间：2026-09-27 至 2026-09-30

评估内容：

回答是否有证据。
证据是否来自正确来源。
是否能识别资料冲突。
是否会把会议提议误认为正式结论。
是否能正确暴露知识缺口。
是否减少人工查找时间。
用户是否认为回答可信且有实际帮助。

阶段结论：

只有当证据回答、来源优先级和知识缺口管理达到要求后，才考虑扩大项目范围或增加复杂技术能力。

四、里程碑

里程碑一：五类试点资料完成

时间：2026-09-12

验收标准：

五份文档内容完整。
文档之间没有明显矛盾。
每份文档标注来源类型和状态。
明确哪些内容是正式事实，哪些内容尚未确认。

里程碑二：首批资料完成接入

时间：2026-09-17

验收标准：

能检索到飞书文档。
能检索到多维表格记录。
能检索到会议记录。
能检索到 GitHub 资料。
权限边界经过检查。

里程碑三：群聊问答试点开始

时间：2026-09-22

验收标准：

用户可以提出自然语言问题。
Agent 可以返回证据和来源。
Agent 可以说明资料缺失。
Agent 可以记录知识缺口。

里程碑四：试点评估完成

时间：2026-09-30

验收标准：

完成典型问题测试。
完成冲突资料测试。
完成缺失资料测试。
完成权限测试。
形成是否扩大范围的建议。

五、当前风险

GitHub 资料缺失会影响开发状态判断。
测试证据缺失会导致测试问题只能回答“暂无证据”。
历史会议记录可能造成错误结论。
文档权限不清可能导致越权访问。
如果源资料质量不足，增加 GraphRAG 也不能解决事实缺失问题。

六、维护要求

每份资料必须包含：

文档类型。
当前状态。
来源优先级。
最近更新时间。
维护责任人。
已确认事项。
未确认事项。
知识缺口。
项目目标指在项目规划之初设定的项目总体目标。项目目标应是被清晰定义的、可实现的且可测量的项目成功标准


使用画板全局绘制出可用于汇报的项目总体概括 （鼠标悬浮在空白行左侧，在“+”工具栏的即可找到插入）





使用多维表格管理项目的事项和目标 （鼠标悬浮在空白行左侧，在“+”工具栏的即可找到插入）
